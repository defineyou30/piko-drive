# v5 입력 화면 — 칩 + 말로 입력 (2026-10-26)

시안: `design/v5/input_redesign.png`. 구현: `app/.../ui/screens/InputScreens.kt`, 음성 `app/.../voice/VoiceInput.kt`(Pleos SpeechToText 3.3.1, ON_DEVICE), 해석 `core/.../agent/VoiceInput.kt`(VoiceParser·InputPresets, 테스트 `VoiceParserTest`).

## 바뀐 것
- 맨 위 문장 요약 = 저장될 내용 ("매주 월·화 16:30, 콩이 수영 / 준비물 수영 가방 · 15분 전에 알려 드려요").
- 누구(아이 카드), 무엇(일정 제목 칩), 요일(평일·주말·매일 + 요일), 시각(시 한 번·분 한 번), 준비물(제목·연령대별 칩), 미리 알림. 키보드는 "+ 직접 입력"일 때만.
- 메모: 언제(큰 버튼 5개) · 누구 · 무엇(상황별 자주 쓰는 메모) · 얼마나(한 번/매번).
- 초안: 저장을 눌러야 목록에 들어감, 취소하면 사라짐. 저장·취소는 화면 아래 고정, "+ 새 일정/메모"는 목록 맨 위 고정.
- 준비물 입력은 일정 한 곳으로: 가족 설정의 요일별 준비물 제거, 도착 때는 그 아이의 지금 무렵(30분 전~2시간 뒤) 일정 준비물을 말한다 (`AgentEngine.itemsNear`).
- 말로 입력(정차 중): 한마디 → 알아들은 칸만 채움, 나머지는 칩으로. 엔진 오류는 한 번 자동 재시도, 최종 결과가 안 오면 마지막 부분 결과 사용.

## E2E (`input/`, `tools/v5_voice.py`)
에뮬레이터엔 마이크가 없어 macOS `say -v Yuna` 음성을 앱 내부 파일로 넣고 실제 Pleos STT로 인식 (디버그 QA 경로).

| 실행 | 일정 음성 "수요일 오후 세시 태권도" | 메모 음성 "콩이가 내릴 때 문 닫혔는지 확인" |
|---|---|---|
| 1 | 엔진 오류 (재시도 전 버전) | "거기가 내릴 때 문 닫혔는지 확인" → 내릴 때마다 "문 닫혔는지 확인" |
| 2 | "수요일 오후 3시 체크인도" → 요일·시각 2칸, 제목 비어 저장 막힘 | "그러니까 내릴 때 …" (본문 규칙 수정 전) |
| 3 | 엔진 오류 → 재시도 → "수요일 오후 3시 태권도" 3칸, 저장 | "콩이가 내릴 때 문 닫혔는지 확인" 정확 |
| 4 | "… 퇴근했는데도" 2칸 | 엔진 오류 → 재시도 → 못 들음 → "잘 못 들었어요" |
| 5 | "수요일 오후 3시 태권도" 3칸, 저장 | "거기가 내릴 때 …" → "문 닫혔는지 확인" |
| 6 (최종) | "… 체크인도" 2칸, 저장 막힘 | "문에 살짝 있는지 확인"으로 잘못 인식 → 요약에 그대로 보임 |

칩만으로 "월·화 16:30 콩이 수영 · 수영 가방" 생성·저장 (키보드 0회).

판단: 요일·시각은 매번 맞는다. 고유어(태권도)·메모 본문은 실행마다 다르다 → 음성은 "빠른 시작", 칩이 "확정". 합성 음성 기준이며 실제 마이크·사람 목소리는 미검증.

## 회귀 (`kidride/`)
v3 루틴 전체 재실행: 도착 준비물이 일정에서 옴 (지우 "도복, 띠", 콩이 "수영 가방"), 보호자 알림 6건 code=200.

## 발견·수정
- 첫 실행에 마이크 권한 창이 먼저 떠서 세션(안전 알림) 시작이 그 답을 기다렸다 → 마이크 권한은 "말로 입력"을 처음 누를 때 묻기.
- 저장 버튼이 긴 편집 화면 아래로 밀려 안 보임 → 화면 아래 고정.
- 저장으로 목록이 늘면 "+ 새 일정" 버튼이 밀려 다른 일정을 누르게 됨 → 목록 맨 위 고정.
- 메모 본문에 주어·군말이 섞임("거기가", "그러니까") → 상황 말 뒤를 본문으로.
- 유치원생 수영 일정에 "낮잠 이불" 후보 → 등원·하원·학교에만.
- 요약 "매주 매일" → "매일".

## 남은 것
- 도착 메모가 차도 쪽 문 경고(긴급)에 끊기면 다시 말하지 않는다.
- Pleos STT의 단어 가중치(`LMBoostConfig`)는 공개 API로 넣을 곳을 찾지 못했다.
