## 4. 새로 발견한 플랫폼 사실
- **Pleos Vehicle SDK 2.3.2 좌석 착석 매핑이 반대**: 차량 신호 착석(2)을 `false`, 빈 좌석(1)을 `true`로 전달 (에뮬레이터 v2.1.0, VHAL 덤프와 대조). AAOS `SEAT_OCCUPANCY`는 서드파티 권한이 없어 SDK 값을 반전해 사용, 실차 재확인 필요.
- SDK 리스너는 "바뀔 때"만 알려준다 → 등록 직후 현재값을 직접 조회해 첫 샘플을 채움.
- 비트맵 픽셀 서체는 ffmpeg에서 크기 조절이 안 됨 → 영상에는 외곽선 버전 사용.

## 6. Codex 2차 재심 (`reviews/eval-codex-judge-r2.md`)
수정본을 Codex에게 다시 보여주고 "아직 남은 문제·수정으로 새로 생긴 문제"만 물었다. 재예측 점수: 차량특화성 7 · 창의성 6 · 기술활용성 7 · 사업성 4.

| 지적 | 판정 | 조치·근거 |
|---|---|---|
| F9 초기화 후 첫 만남 인사가 안 나옴 (프로세스 전역 플래그) | **수용 — 실제 버그** | `PetEngine.allowFirstMeetAgain()`을 초기화에서 호출. 릴리스 v0.2.1에서 초기화 → `SPOKEN GREETING hello_1` 확인 |
| 리포트 시각이 monotonic이라 재시작 후 틀어짐 | 반박 | 저장 시 wall-clock으로 바꿔 기록하고(`DataStorePetRepository.encode`), 읽을 때 현재 기준 monotonic으로 옮긴 뒤 화면에서 다시 wall-clock으로 되돌린다 — 왕복이 상쇄돼 재시작·재부팅과 무관 (코드 검토, 재부팅 실측은 안 함) |
| 조수석 매핑 실차 미검증 | 수용 — 한계로 명시 | 에뮬레이터 VHAL 덤프와 대조해 반전 적용. 기획서·EVIDENCE에 "실차 재확인 필요" 표기 |
| 사업성 수치가 가정 | 수용 — 표기 | MAU·리텐션은 기획서에 "가정"으로 명시, 현재 검증된 것/검증 전 줄 분리 |
| 차량 특화 깊이(내비·충전 경로·HVAC 미연동), 캐릭터 IP 독자성 | 후속 과제 | 출품 범위 밖. 기획서 로드맵에 휴게·충전 안내 단계로 기재 |
| 렌더러·엔진 표정 제한 이중 구현 | 유지 | 엔진은 판정, 렌더러는 화면 깜빡임 방지용. 우선 표정은 양쪽 모두 3초 규칙 공유(`MotionBudget`) |
