# 컨셉 v3 — 피코 드라이브: 아이 라이드 동반자 (확정, 2026-10-26)

## 0. 왜 바꾸나
- v2(운전 습관으로 자라는 픽셀 펫)는 "그래서 뭘 해주는데?"에 답이 약했다. 캐릭터 동반자는 NIO Nomi, 차내 놀이는 Tesla Toybox가 이미 있다.
- 같은 주최(현대차)의 '플레오스 커넥트 앱 아이디어 공모전' 대상은 '창밖동화'다 (위치 + 생성형 AI 동화·퀴즈, https://www.insight.co.kr/news/576146).
  → **아이에게 콘텐츠를 들려주는 앱은 이미 심사위원이 봤다.** v3는 콘텐츠가 아니라 **차량 신호 기반 루틴과 확인**으로 간다. LLM·STT·위치 콘텐츠는 쓰지 않는다.

## 1. 한 줄
**뒷자리 아이에겐 친구, 앞자리 부모에겐 비서.**
- 뒷자리: 피코가 아이 나이에 맞게 벨트·하차·준비물 습관을 만든다.
- 앞자리: **부모는 체크하지 않는다, 차가 체크한다.** 착석·벨트·문·잠금·창문·온도 신호로 자동 확인하고, 출발 전(P)에 한 화면으로 요약하고, 주행 중엔 음성만.
- 대상: 영유아(카시트)부터 중고등학생까지. 나이가 바뀌면 피코의 말과 앞자리 체크 항목이 함께 바뀐다.

## 2. 설계 제약 (에뮬레이터 실측)
- **화면은 운전석 중앙 디스플레이 하나뿐**: 디스플레이 1개(2560x1440), 탑승자 구역은 운전석(zone 0)만 있다. 뒷좌석 화면 없음.
  → 뒷자리 피코는 **목소리 중심**, 화면은 정차 중 보조. 뒷좌석 모니터 연동은 확장안.
- 앞자리 부모 = 운전자. 주행 중 터치 화면 0, 텍스트 0 (v2의 UX 제한 정책 그대로).
- 모든 안전 관련 알림은 **보조 알림**이다. 아이의 존재·부재를 보증하지 않고, 센서를 못 읽으면 "확인 불가"로 표시한다. OEM 경고를 대체하지 않는다.

## 3. 연령별 피코 (뒷자리)
| 연령 | 기본 | 피코가 하는 일 | 앞자리 체크에서 달라지는 것 |
|---|---|---|---|
| 영유아 (0~4세, 카시트) | 켜짐·조용 | 출발 인사 한마디. 쉿 모드면 무음 | 실내 온도 확인, 장거리 휴식 권유(60분), 남김 경고 최우선 |
| 유치원 (5~7세) | 켜짐·활발 | 벨트 매기 놀이, 하차 인사, 칭찬 스티커, 차도 쪽 문 안내 | 차도 쪽 뒷문 열림 경고 |
| 초등 (8~13세) | 켜짐·친구 | 벨트·준비물 습관, 스티커, 요일별 준비물 | 준비물 알림, 하차 시 보호자 알림 |
| 중고등 (14~19세) | **꺼짐** | 원하면 도착 한마디만 | 벨트·하차·보호자 알림은 운전자 쪽에서만 |

중고등은 캐릭터 거부감을 고려해 기본값을 끈다. 앞자리 체크는 그대로 동작한다.

## 4. 앞자리 자동 체크 (부모 비서)
| 시점 | 항목 | 신호 (Pleos Vehicle SDK) | 실측 |
|---|---|---|---|
| 탑승 | 아이별 착석 (좌석 배정) | Seat occupancy ROW_2_L/R | ✅ 읽기·이벤트·주입 (값 반전) |
| 출발 전 | 착석한 좌석의 벨트 | Seat belt buckled ROW_2_L/R | ✅ 읽기. 콘솔 주입 UI 없음 → 데모 패널 "시뮬레이션 입력" |
| 출발 전 | 뒷문 닫힘 | Door position ROW_2_L/R | ✅ 읽기·이벤트·주입 |
| 출발 전 | 문 잠금 | Door lock (4도어 묶음 영역) | ✅ 읽기·이벤트·주입 |
| 출발 전 | 뒷창문 열림 | Window position ROW_2_L/R | ✅ 읽기·이벤트·주입 (0~10 단위) |
| 출발 전 | 실내 온도 (영유아) | HVAC 현재 온도 ROW_1_LEFT | ✅ 읽기 (콘솔은 설정 온도만 바꿈 → 현재값 19.1℃ 고정) |
| 주행 중 | 벨트 풀림 → 운전자 음성 | 벨트 + 속도 | ✅ |
| 주행 중 | 장거리 휴식 권유 | 주행 시간 (앱 계산) | ✅ |
| 주행 중 | 쉿 모드: 피코 무음 + 실내 조명 낮춤 | Ambient brightness (5좌석 묶음, 쓰기 가능) | ✅ 읽기·이벤트·주입 |
| 하차 | **차도 쪽 뒷문 열림 경고** (한국 우측통행 → 기본 왼쪽) | 뒷문 + 기어 + 착석 | ✅ |
| 하차 | 요일별 준비물 | 부모 설정 | 앱 내부 |
| 하차 후 | **뒷좌석 남김 보조 알림** | 운전석·뒷좌석 착석 + 문 잠금 | ✅ (센서 미수신 시 "확인 불가") |
| 출발·도착·하차·남김 | 다른 보호자에게 알림 | 웹훅 (부모가 켤 때만) | ✅ 구현. 시연은 tools/guardian_server.py 보호자 화면 |
| 빼는 것 | 차일드락 | SDK에 API 없음 | ❌ |
| 빼는 것 | 창문 잠금 | 읽기는 되나 콘솔 주입이 SDK에 반영 안 됨 (항상 false) | ⚠️ 오표시 위험 → 제외 |

근거: `qa/v3/probe-cabin.log`, 프로브 코드 `probe/.../ProbeActivity.kt` (`probeRear`, `probeCabin`).

## 5. 루틴 상태머신 (모든 전환은 차량 신호, 부모 조작 0)
```
대기 ─(P에서 뒷좌석 착석)→ 탑승 ─(착석 좌석 벨트 전부 체결)→ 준비 완료
  └ 벨트 미체결 8초 → 피코 벨트 놀이(아이 말투)
준비/탑승 ─(D, 3초 이동)→ 주행
  ├ 미체결 좌석이 있으면 → 운전자 음성 "왼쪽 뒷자리 벨트가 아직이에요"
  ├ 주행 중 벨트 풀림 → 운전자 음성 (30초 간격)
  └ 영유아 동승 60분 / 그 외 120분 → 휴식 권유
주행 ─(P)→ 도착: 요일 준비물 → 차도 쪽 문 감시
도착 ─(뒷좌석 착석 해제)→ 하차: 인사, 스티커, 보호자 알림
도착 ─(운전석 비었는데 뒷좌석 착석 유지 / 문 잠금인데 뒷좌석 착석)→ 남김 보조 알림 (반복, 확인 시 해제)
```

## 6. 캐릭터와 성장 = 칭찬 스티커
- **캐릭터: 헤드램프 렌즈** (시안 2 확정, 2026-10-26). 찹쌀떡 같은 둥근 몸, 이마에 램프 10칸 = 아이의 스티커판.
  스티커를 받을 때마다 가운데부터 한 칸씩 앰버로 켜진다 (헤드램프가 켜지는 차량 문법). 픽셀 격자 v2는 폐기.
- 스티커는 **차량 신호로 확인되는 행동에만**: 재촉 전에 스스로 벨트, 함께 달린 뒤 인도 쪽 문으로 내리기. 유치원·초등만 (영유아는 보호자가 채우고, 중고등은 보상 대상이 아님).
- 판 완성 해금: 1판 = 볼 램프, 2판 = 정수리 램프, 이후 축하 대사. 운전 점수가 아니라 **아이의 습관**이 피코를 키운다.

## 7. 부모 설정 (정차 중만)
- 아이 프로필(최대 2명): **별칭**(실명 대신), 연령대, 좌석(뒷좌석 왼쪽/오른쪽), 피코 켜기/끄기.
- 요일별 준비물 (항목명만, 학원명 저장 안 함).
- 차도 쪽 방향(기본 왼쪽), 보호자 알림 켜기.
- 데이터는 차 안 DataStore에만. 보호자 알림을 켜면 "출발·하차" 이벤트와 별칭만 전송한다고 화면에 명시.

## 8. 차별화
- vs 창밖동화: 이야기(콘텐츠) ↔ **신호 기반 확인과 습관**. 겹치지 않고 보완.
- vs OEM 뒷좌석 알림: 현대 Rear Occupant Alert는 뒷문 개폐 이력 기반. v3는 실제 착석·벨트 신호 + 나이별 대응 + 출발 전 요약 + 보호자 공유.
- vs 학원 셔틀 앱(믿고타요 등): 셔틀 대상, 기사 조작. v3는 **부모 개인 차량**, 조작 없음.

## 9. 사업성 가설 (검증 전, 숫자는 모두 가정)
- 제조사 기본 탑재(가족 차종 패키지) → 기능 차별화. 개인 B2C는 보호자 추가·스티커 테마 정도의 소액.
- 통학차량·보험 제휴는 책임·민감정보 문제가 먼저라 이번 기획에서는 다루지 않는다.

## 10. 재사용 / 신규
- **재사용:** 게이트웨이, 모드 엔진(주행 중 화면 잠금), 말하기 예산, Pleos TTS, 포그라운드 서비스, 테스트 체계.
- **신규:** 뒷좌석·벨트·뒷문·문 잠금·창문·온도·조명 신호, 아이 프로필, 루틴 상태머신, 출발 전 체크 요약, 하차·남김 화면, 스티커, 부모 설정, 캐릭터 리디자인, 보호자 알림.

## 12. 리스크
1. 벨트 주입 불가 → 데모 패널 대체 입력 + "시뮬레이션 입력" 표기. SDK 경로는 코드에 그대로.
2. 착석 반전은 에뮬레이터 기준 → 한 곳에서 관리, 실차 재확인 필요.
3. 남김 알림은 "보조" 표현을 지키고, 센서 미수신이면 "확인 불가".
4. 체크리스트 앱처럼 보일 위험 → 시연은 "신호가 들어오면 알아서 체크되는 장면"으로.
5. 보호자 알림 컷라인 판단 (10/26): **웹훅 + 보호자 화면까지는 지금 구현**(차 → 부모가 정한 URL, 별칭·좌석·시각만). **FCM 푸시·계정·보호자 초대는 로드맵** — 서버 운영 주체와 개인정보 책임이 먼저 정해져야 하고, 시연 가치 대비 3주 안의 위험이 크다.
