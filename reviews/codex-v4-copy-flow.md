## 3. 앞 화면 홈의 정보 위계

현재 배치는 다음과 같다.

- 왼쪽: 피코, 스티커, 안전 기록
- 가운데: 다음 일정, 오늘 일정, 메모
- 오른쪽: 뒷좌석 체크
- 하단: 일정·메모·가족·쉿 모드·설정

근거: `app/src/main/java/com/pikodrive/ui/screens/AgentScreens.kt:81-135`

3초 안에 봐야 할 순서는 현재와 반대다.

운전자 홈에서는 다음 순서가 적절하다.

1. 상단 전체 폭: 지금 필요한 행동  
   - `출발까지 9분`
   - `오른쪽 뒷좌석 벨트 확인 필요`
   - `확인 가능한 항목 3개 정상 · 1개 확인 불가`

2. 좌측 40%: 뒷좌석 상태  
   - 아이별 착석
   - 아이별 벨트
   - 문·잠금
   - 확인 불가 항목

3. 중앙 35%: 다음 일정  
   - 시각
   - 아이
   - 제목
   - 준비물
   - 미리 알림

4. 우측 25%: 상황 메모와 오늘 기록  
   - 지금 발화할 메모
   - 오늘 보조 알림 횟수

5. 하단: 설정 기능  
   - 가족·일정·메모·설정은 동일한 보조 수준
   - `쉿 모드`는 아이가 탑승했을 때만 표시

현재는 피코 이미지와 스티커가 왼쪽 상단을 차지하고, 가장 중요한 안전 상태가 오른쪽 세로 패널에 밀려 있다. 홈의 첫 시선이 캐릭터로 향하고 실제 행동 항목은 오른쪽으로 이동한다.

또한 현재 제목 `확인할 것 3개`는 문제 항목과 정상 항목을 구분하지 않는다.

- `확인할 것 3개` → 위험 또는 미완료처럼 보임
- 실제로는 `미체결 1개`, `확인 불가 2개`처럼 상태별로 분해해야 함

## 5. 심사위원 관점 감점 지점 3개

### 1) 컨셉이 v4가 아니라 “운전 습관 펫 v2”로 보임

감점 근거:

- `Screens.kt:198`
- `LiveScreen.kt:316-318`
- `Screens.kt:279-284`
- `Screens.kt:441-446`

픽셀 성장, 편안한 주행, 성장 가속, 늘어난 픽셀이 반복된다. 심사위원은 “아이 안전·일정 에이전트”보다 “운전 점수에 따라 자라는 펫”으로 이해할 가능성이 높다.

### 2) 보조 알림과 안전 보증의 경계가 불안정함

감점 근거:

- `AgentScreens.kt:200-202`의 `출발 준비 완료`
- `RideScreens.kt:192`의 `확인했어요`
- `RideLines.kt:88-92`의 반복 운전자 음성

센서 기반 보조 시스템인데 완료 문구와 버튼이 실제 안전 확인을 끝낸 것처럼 읽힌다. 안전 제품 심사에서는 이 표현이 치명적이다.

### 3) 부모의 첫 사용 흐름이 완성되지 않음

감점 근거:

- F0 이후 가족 설정 유도 부재: `LiveScreen.kt:98-125`
- 가족 설정의 빈 상태 부재: `RideScreens.kt:230-235`
- 죽은 화면과 이전 컨셉 잔존: `MainActivity.kt:78-88`, `Screens.kt:303-310`
- 숨은 데모 접근: `Screens.kt:167`, `AgentScreens.kt:89-91`

첫 실행 후 부모가 무엇을 먼저 해야 하는지, 아이 등록이 필수인지, 일정·메모를 언제 입력하는지 명확하지 않다. 시연에서는 기능이 많아 보이지만 실제 사용 흐름은 끊겨 있다.
