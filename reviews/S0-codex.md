- **[높음] Go 근거가 충분하지 않음.** 속도·기어·UX Restriction의 수신과 TTS 초기화/중단 단위 동작은 확인됐지만, S0 필수 증거인 **API별 성공·실패 로그 표**가 문서에 정리되어 있지 않다. 실패 사례도 `probe-drive-log.txt`의 초기 TTS 호출 오류, 권한 부재(SecurityException) 미재현 등으로 체계화되지 않았다.
- **[높음] S3 조건을 충족했다고 보기 어려움.** TTS 로그는 `stop()` 호출 후 3ms를 측정했지만, **발화 중 실제 기어 D→R 전환에 따른 자동 중단**을 검증하지 않았다. 따라서 “후진 1초 내 중단 기준 충족 가능”은 가능성이지 통과 증거가 아니다.
- **[중간] 급제동 결론이 과장됨.** 60→10km/h의 단일 시나리오에서 −16km/h/s가 관측된 것뿐이며, 이미 로그에 샘플링 손실이 명시돼 있다. −10 임계값이 다양한 속도·감속 패턴·샘플 간격에서도 안정적으로 검출된다는 근거는 없다.
- **[중간] `VehicleGateway` 계약과의 차이.** 로그의 속도 이벤트는 대체로 100~200ms지만, 프로브가 1초 하트비트를 보장하는 Gateway 구현·재방출을 검증한 것은 아니다. `VehicleGateway`는 값이 변하지 않아도 최대 1초마다 snapshot을 내보내야 하므로 S3 어댑터에서 명시적으로 heartbeat를 구현해야 한다.
- **[높음] 단위 변환을 S3 계약에 고정해야 함.** Virtual Console 입력은 정수 km/h, AAOS 속도 출력은 m/s, 코어 모델은 km/h다. `m/s × 3.6` 변환과 반올림·양자화 정책을 `PleosVehicleGateway` 한 곳에 고정하고, 감지기에는 이미 변환된 km/h와 동일한 시간 기준만 전달해야 한다.
- **[높음] 권한 실패를 안전 상태로 처리해야 함.** `CAR_SPEED`, `CAR_DRIVE`, `TTS_SERVICE` 권한별 성공·거부·SecurityException을 별도 검증해야 한다. 권한 또는 UX Restriction이 미확인(null)인 동안은 정차/대화 가능 상태로 추정하지 말고 무음·비대화 모드로 유지해야 한다.
- **[높음] 샘플링 특성이 임계값에 직접 영향.** 현재 프로브는 `SENSOR_RATE_ONCHANGE`와 콘솔의 계단형 정수 입력을 사용한다. 이벤트 간격, 중복 재전송, 값 양자화, 지연 때문에 미분값이 실제보다 작거나 커질 수 있으므로 임계값 −10을 그대로 S3에 이식하면 오검출·미검출 위험이 있다. 실측 간격/지연을 기록하고, 최대 간격 초과 시 미분을 계산하지 않는 정책을 유지해야 한다.
- **[중간] UX Restriction 검증 범위 부족.** D 진입 시 `required=true, active=80`, P 복귀 시 해제는 확인했지만 R 전환, 초기값 미확인, 리스너 지연·누락, 앱 재시작 시 안전 부팅은 검증하지 않았다. `uxRestriction=true` 계약과 결합해 미확인 상태를 보수적으로 처리해야 한다.
- **[높음] 프로브가 놓친 검증.** 실제 발화 중 D→R 전환, R→D 복귀 시 이전 이벤트/TTS 취소, 속도 권한 거부, 기어 권한 거부, TTS 권한 거부, UX 리스너 미수신, 데이터 단절 및 1초 heartbeat, out-of-order timestamp, 장시간 정속 중 heartbeat를 검증하지 않았다.
- **[중간] `vconsole.py` HTTP 신뢰성 문제.** 모든 요청이 단일 시도·5초 timeout이며 상태 코드/응답 JSON 형식/본문 오류를 검증하지 않는다. heartbeat 실패를 무시하므로 세션이 끊긴 채 시나리오가 계속될 수 있다.
- **[중간] 시나리오 실행 신뢰성 문제.** 명령 성공 여부를 확인하지 않고 다음 단계로 진행하며, `speed()`의 `round()`가 Python banker’s rounding을 사용한다. 정수 km/h 양자화 오차와 실제 차량 이벤트 시각의 차이도 로그에 별도 기록되지 않는다.
- **[중간] 종료 처리 문제.** heartbeat 스레드를 중지하지만 마지막 요청 완료를 기다리지 않고 종료한다. `KeyboardInterrupt`·중간 HTTP 실패·잘못된 인자에 대한 명확한 실패 종료 코드도 없다.
- **[낮음] 관찰성 부족.** 호스트 로그에는 명령 시각만 있고 HTTP 응답, 콘솔 반영 시각, 실제 차량 API 수신 시각을 상관시킬 request ID가 없어 지연·유실 분석이 어렵다.

**S0 게이트 판정: 조건부 No-Go — 차량 API 접근성은 확인됐지만, API별 성공·실패 표와 실제 “발화 중 후진 전환 후 1초 내 중단” 증거가 없어 S3 이관을 정식 승인할 수 없음.**
